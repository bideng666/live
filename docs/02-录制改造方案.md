# 直播录制改造方案

目标很明确：**把抖音直播的画面和音频录到本地文件**。不做切片，不做转码。

---

## 一、为什么不能直接用原项目的播放器录

原项目的播放链路是 `getPlayUrls` → `Media(url)` → media_kit（libmpv）播放。看着只要让 mpv 顺便把流写盘就行，但有两个硬伤：

**1. CDN 地址会过期。** 抖音的流地址带 `expire` 签名，几十分钟就失效。而原项目的断流处理是（`live_room_controller.dart:445`）：

```dart
void mediaEnd() async {
  if (mediaErrorRetryCount < 2) {
    mediaErrorRetryCount += 1;
    setPlayer();          // → player.jump(currentLineIndex)
    return;
  }
}
```

`player.jump()` 重放的是**同一条已经过期的地址**，最多重试 2 次。看直播没问题（断了手动刷新页面），但录制要连续跑几小时，必然断在半路。

**2. `getPlayUrls` 不会重新签名。** 它只是把 `quality.data` 复制一份返回（`douyin_site.dart:637`）。想拿到新地址，必须重跑 `getRoomDetail` → `getPlayQualites` 整个流程。

所以录制器必须自己控制"重新取地址"这件事，不能依赖播放器。

## 二、方案：与播放器解耦的独立拉流录制器

```
LiveRoomController（宿主，已有取流能力）
   │  提供三个闭包
   ├── roomInfoProvider : 拿主播昵称 → 文件命名
   ├── playUrlResolver  : 重跑 房间详情→清晰度→播放地址，拿**新签名**的地址
   └── liveChecker      : getLiveStatus，判断是重连还是收工
   │
   ▼
RoomRecorderController（app 层，只管 UI 状态 + 开关）
   │
   ▼
LiveRecorder（core 层，纯 Dart，与播放器无关）
   │
   └── 循环：取地址 → 拉流写盘 → 断了就重新取地址 → 接着写
```

产物：

```
SimpleLiveRecords/
├── douyin_主播昵称_20260923_024000_001.flv    ← 一次连续连接的录像
└── douyin_主播昵称_20260923_024000_002.flv    ← 断流重连后新开的文件
```

写出来的是 CDN 原始字节（抖音是 FLV），**没有转码**，画质和直播完全一致，也不吃 CPU。

## 三、四个关键设计决策

### 1. 每次重连都重新取地址

对应上文第 1 个硬伤。`playUrlResolver` 刻意**不复用页面加载时缓存的 `detail.value`**，而是重新调 `getRoomDetail`：

```dart
Future<LivePlayUrl> _resolveRecordPlayUrl() async {
  final freshDetail = await site.liveSite.getRoomDetail(roomId: roomId);
  final freshQualities = await site.liveSite.getPlayQualites(detail: freshDetail);
  ...
  return site.liveSite.getPlayUrls(detail: freshDetail, quality: quality);
}
```

这样不管录多久，每次拿到的都是新签名的地址。清晰度尽量和当前观看的一致。

### 2. 默认一个文件，断流才新开

默认不按时间切分（`segmentDuration = Duration.zero`），一次连续连接写成一个文件，符合"我就是想录下来"的直觉。

只有连接真的断了才会新开一个文件。**为什么不接着往原文件里追加？** 因为每次重新拉流，CDN 都会从头给一份带 FLV 头的完整流，把第二份的头直接怼到文件中间，播放器会读坏。所以断流就新开一个文件——这是最简单也不会出错的做法。

需要定时切分（比如方便分次上传）时，把 `segmentDuration` 设成 10 分钟之类即可。

### 3. 只校验 FLV 魔数，不解析容器

录制器对流的处理就是"收到字节 → 写文件"，不解码、不解析容器、不算时间戳。唯一的检查是开头三个字节必须是 `FLV`：

```dart
if (chunk.length >= 3 &&
    !(chunk[0] == 0x46 && chunk[1] == 0x4C && chunk[2] == 0x56)) {
  throw Exception('返回内容不是 FLV（地址可能被防盗链拦截）');
}
```

这个检查很值：地址被风控时 CDN 会返回一个错误页而不是流，不做检查就会把 HTML 当视频写进去，录完才发现文件是坏的。检查了就能立刻报错并重连。

### 4. HLS 兜底

抖音的 FLV 地址通常都能用，但如果某个 CDN 节点拒绝，`_pumpHls` 会走 HLS 路径：解析 m3u8、顺序拉 `.ts` 分片追加到同一个文件。MPEG-TS 允许直接拼接，不需要像 FLV 那样靠重连保证可播性。

## 四、集成步骤

### 1. core 层（纯 Dart，无新依赖）

```bash
cp -r simple_live_core/lib/src/recorder  <项目>/simple_live_core/lib/src/
```

然后在 `<项目>/simple_live_core/lib/simple_live_core.dart` 末尾加一行：

```dart
export 'src/recorder/recorder.dart';
```

| 文件 | 行数 | 作用 |
| --- | --- | --- |
| `recorder_options.dart` | ~100 | 录制参数、房间信息、路径/文件名工具 |
| `live_recorder.dart` | ~470 | 录制主循环：取地址、拉流、写盘、重连、HLS 兜底 |
| `recorder.dart` | ~8 | 汇总 export |

不需要改 `pubspec.yaml`：dio 已经是 core 的依赖。

### 2. app 层

```bash
cp -r simple_live_app/lib/modules/live_room/recorder  <项目>/simple_live_app/lib/modules/live_room/
```

| 文件 | 作用 |
| --- | --- |
| `recorder/room_recorder.dart` | 录制控制器：UI 状态、开关、默认输出目录 |
| `recorder/recorder_button.dart` | 播放器顶栏的录制按钮 + 详情面板 |

### 3. 打补丁

三个文件的小改动已生成 unified diff：

```bash
cd <项目根目录>
git apply patches/simple_live_core.dart.patch
git apply patches/live_room_controller.dart.patch
git apply patches/player_controls.dart.patch
```

改动内容：

- **`live_room_controller.dart`**：加 import；构造函数里创建 `recorder` 并提供两个闭包（核心是 `_resolveRecordPlayUrl` 里"重新取地址"那段）；`onClose` 里加 `recorder.stop()`。
- **`player_controls.dart`**：在截图按钮后面插入 `RecorderButton(recorder: controller.recorder)`。

### 4. 编译

```bash
cd simple_live_app && flutter pub get && flutter run -d windows
```

## 五、怎么验证录得对不对

录一段（建议超过 30 秒），然后：

```bash
# 看时长、编码、分辨率
ffprobe -v error -show_entries format=duration,size -show_streams 录制的文件.flv
```

应该看到 `h264` + `aac`，时长和你录的时间接近。**如果时长明显偏短或文件只有几十 KB，说明流没接上**，检查网络或换个房间试。

验证断流重连：录制中拔网线几秒再恢复，观察按钮的详情面板——状态应显示「重连中」，之后回到「录制中」，文件数变成 2。而不是整场结束。

## 六、已知限制

| 限制 | 说明 |
| --- | --- |
| 断流会多出一个文件 | 见设计决策 2，这是保证文件可播的代价 |
| 带宽翻倍 | 录制自己拉一路，和播放各占一份。想省带宽可以录制时暂停播放 |
| 依赖抖音签名算法 | `a_bogus` 变了要跟着更新上游的 `douyin_sign.dart`，与录制逻辑无关 |
| 没有录制设置界面 | 分片时长、输出目录目前是代码里的默认值，改 `RoomRecorderController._defaultOptions` 即可 |
| 录制中不校验内容完整性 | 只检查 FLV 魔数。如果 CDN 中途给了坏数据，文件里就会有坏数据（概率极低） |

## 七、合规提醒

抖音用户协议通常禁止未经授权的抓取与二次传播；录制他人直播并分发可能侵犯著作权与肖像权。请仅在获得主播授权或个人学习研究等合法范围内使用。
