# 使用教程：录制抖音直播的画面和音频

面向完全没接触过这个项目的人。跟着走一遍，大约 30 分钟能录下第一段直播。

## 0. 全流程

```
① 推代码到 GitHub          5 分钟（只需做一次）
        ↓
② 云端打包出 exe           10~20 分钟（改代码才需要重做）
        ↓
③ 解压运行，进直播间        1 分钟
        ↓
④ 点录制按钮，挂着          和直播一样长
        ↓
⑤ 拿到视频文件              在 文档\SimpleLiveRecords 里
```

录制是**实时**的：主播播 3 小时，你就要挂 3 小时。没有"加速下载"这回事。

## 1. 准备工作

### 1.1 你需要什么

| 用途 | 需要什么 |
| --- | --- |
| 打包 | GitHub 账号、Git for Windows |
| 录制 | 无（exe 自带全部依赖） |
| 事后检查文件 | ffmpeg（可选） |

**录制本身什么额外东西都不用装。**

### 1.2 装 Git for Windows

到 <https://git-scm.com/download/win> 下载安装，一路默认。

装完按 Win+R 输入 `cmd` 回车，验证：

```bat
git --version
```

能打印版本号就行。

### 1.3 （可选）装 ffmpeg

只有想用 `ffprobe` 检查录制文件是否正常时才需要。

到 <https://www.gyan.dev/ffmpeg/builds/> 下载 `ffmpeg-release-essentials.zip`，解压到比如 `D:\ffmpeg`，然后把 `D:\ffmpeg\bin` 加进系统 PATH：

1. Win+R → `sysdm.cpl` → 回车
2. 「高级」→「环境变量」
3. 「系统变量」里找到 `Path` → 双击 → 「新建」→ 粘贴 `D:\ffmpeg\bin` → 一路确定
4. **重开一个 cmd 窗口**（必须重开）

验证：`ffprobe -version`

## 2. 第一步：云端打包出 Windows 版

### 2.1 建仓库并推代码

把 kit 解压到一个目录，然后在那个目录里执行：

```bat
cd /d <kit 解压目录>
git init
git add -A
git commit -m "dart_simple_live recording kit"
```

**提交后务必做一次自检**——`git add -A` 不会提示被 `.gitignore` 排除的文件，如果漏了文件你会以为推成功了，直到云端构建报出一个看不出原因的错：

```bat
git ls-files | findstr recorder
```

应该输出 **5 行**：

```
simple_live_app/lib/modules/live_room/recorder/recorder_button.dart
simple_live_app/lib/modules/live_room/recorder/room_recorder.dart
simple_live_core/lib/src/recorder/live_recorder.dart
simple_live_core/lib/src/recorder/recorder.dart
simple_live_core/lib/src/recorder/recorder_options.dart
```

**少于 5 行就停下来**，检查 `.gitignore` 里有没有写成 `src/`（不带前导斜杠）的规则——git 的这个模式会匹配任意层级的 `src` 目录，把 `simple_live_core/lib/src/` 整个排除掉。正确写法是 `/src/`。

到 GitHub 网页上建一个**空仓库**（不要勾选 "Add a README file"），假设叫 `dsl-record`。然后：

```bat
git remote add origin https://github.com/<你的用户名>/dsl-record.git
git branch -M main
git push -u origin main
```

> 私有仓库也可以，功能完全一样。首次 push 会弹窗登录 GitHub。

### 2.2 跑 Actions

1. 打开仓库页面 → 上方 **Actions** 标签
2. 左侧列表点 **build-windows**
3. 右边 **Run workflow** → 再点绿色的 **Run workflow**
4. 刷新页面，会看到一个正在运行的任务

三个可选参数一般不用改（Flutter 版本 `3.38.x`、上游 tag `v1.11.4`、是否构建 msix）。

等 10~20 分钟。首次慢一些（要下载 Flutter 引擎和依赖），之后有缓存会快很多。

### 2.3 下载产物

任务变成绿色勾后，点进这次运行，页面**最下方**有 **Artifacts**，下载 `SimpleLive-windows.zip`。

> 任务变成红色叉就是失败了，点进去搜 `[XX]` 能快速定位。

## 3. 第二步：运行程序

### 3.1 解压

把 `SimpleLive-windows.zip` 解压到任意目录，比如 `D:\SimpleLive`。

**必须整个文件夹一起解压，不能只拷 exe。** exe 依赖同目录的 dll 和 `data\`，单独拷 exe 打不开。

### 3.2 过 SmartScreen 警告

exe 没有代码签名，首次运行 Windows 会拦一下：

1. 双击 exe，出现蓝色「Windows 已保护你的电脑」
2. 点 **更多信息** → **仍要运行**

杀毒软件也可能误报（同样是没签名），加白名单即可。

### 3.3 找到录制按钮

1. 程序启动后，首页点 **抖音直播**
2. 搜索框输入主播名或直播间号，进一个**正在直播**的房间
3. 播放器顶部工具栏，**截图按钮的右边**有一个**红色圆点**按钮 —— 这就是录制按钮

---

## 4. 第三步：录制

### 4.1 开始

点一下红色圆点。会弹出提示：

```
开始录制
C:\Users\<你>\Documents\SimpleLiveRecords
```

按钮变成**红色方块**，表示正在录制。

此时你可以在 App 里正常看直播，也可以切到别的房间——**录制不受影响**，因为录制器自己拉了一路流，和播放器是独立的。

### 4.2 看录制状态

**长按**录制按钮，弹出详情：

| 项 | 说明 |
| --- | --- |
| 状态 | 录制中 / 重连中 / 已停止 |
| 时长 | 已录制多久 |
| 体积 | 已写入多少 |
| 文件数 | 正常是 1；断流重连后会变多 |
| 输出目录 | 可以点「复制输出目录」 |

### 4.3 输出长什么样

```
C:\Users\<你>\Documents\SimpleLiveRecords\
├── douyin_主播昵称_20260923_024000_001.flv
└── douyin_主播昵称_20260923_024000_002.flv    ← 断流重连后才会出现
```

- 文件名里的时间是**开始录制**的时刻
- **一次连续连接写一个文件**。网络没断就是一个文件
- 写出来的是 CDN 原始流，**没有转码**，画质和直播一致
- 文件之间可能有几秒缺口（断流重连导致的），这是正常的

### 4.4 录多久、占多大

先录几分钟，然后用 ffprobe 看实际码率：

```bat
ffprobe -v error -show_entries format=bit_rate -of default=nw=1:nk=1 "C:\Users\<你>\Documents\SimpleLiveRecords\douyin_主播昵称_20260923_024000_001.flv"
```

得到的是 bit/s。除以 8 再乘 3600 就是每小时的字节约数。参考量级：

| 画质 | 大致码率 | 每小时约 |
| --- | --- | --- |
| 720p | 1.5~2.5 Mbps | 0.7~1.1 GB |
| 1080p | 3~6 Mbps | 1.4~2.7 GB |
| 蓝光/原画 | 6~10 Mbps | 2.7~4.5 GB |

仅供参考，以你实测的为准。

### 4.5 停止

再点一次录制按钮 → 确认 → 停止。

**离开直播间页面也会自动停止录制。** 所以想录完整场，就别退出房间。

### 4.6 录制中会看到的情况

| 现象 | 正常吗 | 说明 |
| --- | --- | --- |
| 状态显示「重连中」 | 正常 | CDN 断流了，会自动重新取地址续录 |
| 文件数变成 2 | 正常 | 重连后新开了一个文件 |
| 状态显示「直播已结束」 | 正常 | 主播下播了，录制自动收工 |
| 连续 5 次重连失败 | 需要注意 | 一般是网络断了，或被风控 |

## 5. 录完之后

### 5.1 检查文件是否正常

```bat
ffprobe -v error -show_entries format=duration,size -show_streams "录制的文件.flv"
```

应该看到：

```
codec_name=h264          ← 视频编码
codec_name=aac           ← 音频编码
width=1920  height=1080  ← 分辨率
duration=3600.123        ← 时长，应该和你录的时间接近
size=1234567890          ← 文件大小
```

**如果时长明显偏短、或者文件只有几十 KB，说明流没接上**，检查网络或换个房间重录。

### 5.2 用什么播放

**ffplay**（装 ffmpeg 时自带）：

```bat
ffplay "录制的文件.flv"
```

快捷键：`空格` 暂停，`←` `→` 快退/快进 10 秒，`o` 显示时间，`f` 全屏，`q` 退出。

或者 VLC / PotPlayer 都行。**别用 Windows 自带的「电影和电视」**，它经常打不开 FLV 里的某些编码。

### 5.3 想转成 mp4

如果需要 mp4（有些软件不认 flv），可以**无损转封装**，不重新编码、不损失画质、几秒完成：

```bat
ffmpeg -i "录制的文件.flv" -c copy -movflags +faststart "输出.mp4"
```

### 5.4 想把多个文件接起来

如果断流生成了多个文件，要合成一个：

先建一个文本文件 `list.txt`，每行写一个文件：

```
file 'C:/Users/你/Documents/SimpleLiveRecords/douyin_主播_20260923_024000_001.flv'
file 'C:/Users/你/Documents/SimpleLiveRecords/douyin_主播_20260923_024000_002.flv'
```

注意路径用**正斜杠**，单引号包起来。然后：

```bat
ffmpeg -f concat -safe 0 -i list.txt -c copy 合成.flv
```

因为是同一个直播的连续流，编码参数一致，所以可以无损拼接。

## 6. 常见问题排查

### 打包相关

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| Actions 里找不到 build-windows | workflow 没推上去 | 确认仓库里有 `.github/workflows/build-windows.yml` |
| 日志里 `kit 完整性校验` 报缺少文件 | 多半是 `.gitignore` 把 `simple_live_core/lib/src/` 排除了 | 见 2.1 的自检；把 `src/` 改成 `/src/` 后重新提交推送 |
| `[XX] 找不到改造 kit 目录` | 同上（这是修复前的老报错） | 同上 |
| `[XX] 找不到 flutter` | Flutter 版本参数写错 | 用默认的 `3.38.x` |
| `[XX] 打包脚本失败` | 看上面几行的 `[XX]` | 真正的错误在那里 |
| `[XX] 未检测到 Visual Studio 的 C++ 桌面开发组件` | 本地打包时缺 VS | 用云端打包，或装 VS 2022 + C++ 桌面开发 |
| `[XX] 下载源码包失败` | 网络不通 | 检查能否访问 `codeload.github.com` |
| `flutter pub get` 卡住 | 访问 pub.dev 慢 | 重跑一次 |

### 运行相关

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 双击 exe 没反应 | 只拷了 exe | 整个文件夹一起用 |
| 蓝色 SmartScreen 拦截 | 未签名 | 更多信息 → 仍要运行 |
| 顶栏没有红色圆点按钮 | 用的不是这个 kit 打的包 | 确认是自己打包的版本 |
| 点录制没反应 | 主播未开播 | 只有开播中的房间能录 |

### 录制相关

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 一直「重连中」 | 网络不稳或被风控 | 换网络；或调大 `RecorderOptions.reconnectDelay` |
| 文件只有几十 KB | 地址被 CDN 拒绝 | 检查是否开了代理；换个房间试 |
| 录到一半停了 | 连续 5 次失败，或主播下播 | 看详情面板的「状态」 |
| 文件数很多 | 网络反复抖动 | 正常现象，事后可以用 ffmpeg 拼接（见 5.4） |
| 录制中画面卡但录像正常 | 播放器自己的问题 | 录制是独立拉流，不受播放影响 |

### 排查用命令

```bat
:: 看文件是否完整
ffprobe -v error -show_entries format=duration,size -show_streams "文件.flv"

:: 看码率
ffprobe -v error -show_entries format=bit_rate -of default=nw=1:nk=1 "文件.flv"
```

## 7. 合规提醒

抖音用户协议通常禁止未经授权的抓取与二次传播；录制他人直播并分发可能侵犯著作权与肖像权。

请仅在**获得主播授权**或**个人学习研究**等合法范围内使用，不要用于批量搬运。
