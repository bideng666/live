# 抖音直播取流链路分析（dart_simple_live v1.11.4）

分析对象：`lostars/dart_simple_live` tag `v1.11.4`（commit `6b86e80`，是 `xiaoyaocz/dart_simple_live` 的 fork，含完整源码）。
仓库结构分三层：

| 目录 | 作用 |

## 二、四个关键实现细节

### 1. 签名：`a_bogus` + `msToken`

`_getRoomDataByApi` 拿到的接口地址不是直接请求的，而是先过一遍签名：

```dart
var requestUrl = DouyinSign.getAbogusUrl(uri.toString(), kDefaultUserAgent);
var result = await HttpClient.instance.getJson(requestUrl, header: requestHeader);
```

`getAbogusUrl`（`douyin_sign.dart:10651`）做三件事：

1. 生成 107 位随机 `msToken`；
2. 用 `dart_quickjs` 起一个 JS 运行时，`eval` 内嵌的 `kABogus` JS（`douyin_sign.dart:7`，抖音 web 端 `a_bogus` 算法的 JS 移植，含 RC4、SM3 等）；
3. 执行 `getABogus(query, userAgent)` 得到签名，拼成 `url&msToken=...&a_bogus=...`。

注意 UA 参与签名计算，所以**请求头里的 UA 必须和传给 `getAbogusUrl` 的一致**，否则接口返回风控页。

### 2. Cookie 只需要 `ttwid`

`kDefaultCookie`（`douyin_site.dart:29`）里硬编码了一个 `ttwid`，注释说明经测试只需这一个字段就能拿到包括蓝光在内的所有画质，`LOGIN_STATUS` 等都可选。这对录制很友好：不需要账号。

### 3. `stream_url` 的两种格式

这是最容易踩坑的地方，`getPlayQualites` 里做了分支（`douyin_site.dart:561-618`）：

- **新格式**：`pull_data.stream_data` 是字符串，内容是 `{"data": {"<sdk_key>": {"main": {"flv": "...", "hls": "..."}}}}`，用 `qualities[i].sdk_key` 去索引。
- **旧格式**：`stream_data` 为空或非 JSON，退回读 `flv_pull_url` / `hls_pull_url_map`，这两个是按画质代号（`FULL_HD1` / `HD1` / `SD1` / `SD2`）索引的 Map，代码用 `index = 列表长度 - level` 对齐。

每个画质的 `data` 是 `[flv地址, hls地址]`——**先 add flv 再 add hls**（`douyin_site.dart:596-607`），录制时取 `data[0]` 就是 FLV。

### 4. 地址会过期，而原项目不会刷新

`getPlayUrls` 只是把 `quality.data` 复制一份返回（`douyin_site.dart:637`），**不做任何重新签名**。CDN 地址上的签名（`expire`、`wsSecret` 之类）有时效，几十分钟量级。

而播放器的断流处理是：

```dart
// live_room_controller.dart:445
void mediaEnd() async {
  if (mediaErrorRetryCount < 2) {
    mediaErrorRetryCount += 1;
    setPlayer();          // → player.jump(currentLineIndex)
    return;
  }
}
```

`player.jump()` 重放的是**同一条已过期的地址**。短时间看直播没问题，但做长时间录制/挂机必然断。这是录制改造必须解决的第一问题。

## 三、可复用的核心逻辑

按复用价值排序：

1. **地址解析三件套**：`getRoomDetail` → `getPlayQualites` → `getPlayUrls`，加上背后的 `DouyinSign.getAbogusUrl`。这是整个项目最有价值的资产。`simple_live_core` 是纯 Dart 包（依赖只有 dio / protobuf / crypto / dart_quickjs 等），**可以脱离 Flutter 直接在 Dart 服务端项目里引用**。
2. **`LiveSite` 站点抽象**（`interface/live_site.dart`）：录制层只依赖这个接口，因此录制器写一次就能同时支持抖音/斗鱼/虎牙/B站，加平台不用改录制代码。
3. **`LivePlayQuality.data` 的 `[flv, hls]` 约定**：顺序固定是「先 flv 后 hls」。FLV 是完整字节流，一个 HTTP 连接就能持续拿到数据；HLS 需要按 m3u8 逐个拉分片。录制优先选 FLV。
4. **弹幕 WebSocket + protobuf 解码**（`douyin_danmaku.dart`）：本项目录制用不到，但如果以后要连弹幕一起存，这是现成的实现。`wss://webcast3-ws-web-lq.douyin.com/webcast/im/push/v2/`，需要 `room_id`（一次性 ID）+ `signature`（`DouyinSign.getSignature`，用内嵌 `kWebMsSDK` JS 算），消息是 protobuf（`proto/douyin.proto`）gzip 压缩的 `PushFrame`，解出 `WebcastChatMessage`。
5. **`LiveMessage` 统一消息模型**：`{type, userName, message, color}`，与平台无关。

## 四、录制场景下的三个坑

| 坑 | 说明 | 应对 |
| --- | --- | --- |
| 地址过期 | 见上文 2.4 | 每次重连/每片都重跑 `getRoomDetail` + `getPlayQualites` |
| webRid vs roomId | `roomId` 每次开播都变（19 位），`webRid` 固定（11–12 位）。`douyin_site.dart:246` 用长度 ≤16 判断 | 入参、收藏、录制目录命名统一用 webRid |
| `status == 4` 特例 | 抖音对"未开播"返回 4，此时 `roomId` 已失效，代码会退回用 webRid 再查一次（`douyin_site.dart:276`） | 录制器判断"是否还在播"时用 `getLiveStatus`（内部走 `getRoomDetail`），不要自己解析状态码 |

另外：`getRoomDetail` 每次都会起一次 QuickJS 算签名，有一定开销。录制器的重连间隔不要设得太短（默认 3 秒足够），避免高频签名请求触发风控。
